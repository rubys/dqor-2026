A framework is a language without a compiler.

The thesis in seven words.

The bill

Three things a compiler does that a library cannot.

  • A compiler answers once. A library re-answers.
  • A compiler sees the whole program. A library sees the call it's in.
  • A compiler can change the target. A library is bound to its host.
Three things a compiler does that a library cannot. Each comes back: answering once is the performance table, the whole program is the seams in act 4, changing the target is the ten languages.

Rails is to web applications
what SQL is to data.

SQL has a compiler. It's called the query planner.

Who here has ever tuned a query without changing the SQL?

SQL is the declarative language that won, and its compiler is the query planner. Why it survived is "Except one", two slides on.

So why did they die?

Not because declarative was wrong.

  • The compilers were the expensive part. Every target was a team.
  • Revenue was runtime licenses. No reason to compile you onto anyone else's platform.
  • Green screens → Windows → the web. One target, one vendor: they didn't move.
The vendors' business model was structurally opposed to the portability that would have saved the language.

Except one

SQL had many vendors and no owner.

Competitors shared the cost of the compiler. When the platform moved, SQL moved with it.

IBM's CSP ran on every IBM platform. Many targets. One owner. It never died, and it never became SQL.

CSP, first-hand: I worked at IBM in the 1990s alongside the group that developed and maintained it. Two variables: many targets (CSP had them) and many keepers (only SQL had them). Act 5 is about the second.

A rule a newcomer wrote

A pull request made check quiet about a construct. The emitted program didn't run it.

The fix wasn't to reject the pull request. It was a rule for everyone:

A diagnostic you remove is a claim that the emitted program runs. — AGENTS.md, invariant 6, added 2026-09-28

Now every such change has to come with a test that runs the output. The project got stricter because someone new showed up.

The contributor did nothing wrong; the project hadn't said what "supported" meant. The rule is commit 2b2a058c, and tests/emit_and_run.rs is the harness that enforces it. Contributions change the rules, not just the code.

Why nobody noticed

has_many is define_method.

Lisp did language-as-library with macros, at compile time. Ruby did it at runtime. At the source level both are method calls, so the boundary is invisible — and it runs through the middle of every model, a def three lines below a belongs_to.

Appendix. Prior art: Racket's "Languages as Libraries" (PLDI 2011).

Re-answered

Rails answers belongs_to at boot. Then, every request, it re-answers the questions that follow from it: which columns, which table, which route, which template, which filters.

Threads, fibers, processes

The compiled binary runs green threads in one process. At twelve workers the collector has the world stopped more than half the time.

Under load, fibers measured faster than threads on both apps we tried. One heap per core might be the answer. I don't know yet.
